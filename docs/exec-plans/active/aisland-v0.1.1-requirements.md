# AIsland v0.1.1 需求与阶段验收计划

日期：2026-10-03（北京时间）。状态：`PLAN_CONFIRMED_STAGE_1_REVIEW_PENDING`。

本文件记录用户已经确认的功能范围、计划和验收目标。用户已确认计划，要求三个需求在实现过程中分别停下来确认阶段效果。第一阶段已制作独立的声音与引导审阅原型；正式运行时尚未修改，尚未安装或发布新版本。具体审阅结果与后续分工见 [阶段 1 记录](./aisland-v0.1.1-stage-1.md)。工作目录和构建 5 起点见 [交接文档](./aisland-v0.1.1-handoff.md)，接入证据和视听研究边界见 [调研记录](../../references/aisland-v0.1.1-discovery.md)。

## 1. 已确认的范围

用户明确提出三项需求：

1. 接入 Hermes CLI、MiniMax Code 桌面端、DeepSeek Harness 桌面端、豆包工作桌面端、千问办公桌面端。
2. 在现有声音模块增加用户导入 MP3 的选项。
3. 制作类似 Dia 首次安装介绍的引导体验，充分调研每一步的画面、音效和震感。

用户在需求梳理中进一步确认：

- 新工具接入覆盖真实任务状态、完成通知和点击回到正确会话；工具提供接口时支持审批和回答。
- 自定义声音分别用于任务完成、等待审批、等待回答。
- 引导采用全屏沉浸开场，再进入简洁设置流程。
- 音效是核心要求，必须结合动效转场分析和验收。
- Dia 是酷炫视听效果的参考；可结合其他相关案例，具体设计采用 AIsland 自己的视觉与原创声音。
- 可将独立工作委派给 `gpt-6.1-sol`、`high` 子 Agent；需要转交 ZCode 时先准备详细任务说明，由用户转交。
- 接入、声音、引导各自到效果审阅节点必须暂停，收到用户确认后才继续相关后续实施。

v0.1.0 构建 5 的公证发布继续由原窗口负责。本计划使用准备好的 `feat/v0.1.1` 分支；后续打包使用 0.1.1、构建号 6 或更高。

## 2. 新工具接入

### 用户结果

用户能在刘海看到某个工具的真实任务状态，得到完成提示，并点击回到发出该状态的会话。多个任务同时运行时，名称、状态和跳转目标保持对应。审批和问答分别按各来源的实际能力接入。

### 验收草案

| 编号 | 场景 | 可观察的通过条件 |
| --- | --- | --- |
| A1 | 五个来源各执行一个真实任务 | 工具身份正确；运行与完成状态对应真实任务，不以进程存在或短时间无事件代替任务状态 |
| A2 | 同一来源两个任务并行 | 状态、标题、会话 ID 和通知归属正确；一个任务完成不会结束另一个 |
| A3 | 后台任务完成 | 完成通知恰当出现，使用“任务完成”类别的声音；发现或恢复旧会话不重复制造新完成提示 |
| A4 | 从刘海点击任务 | 正确会话被选中，来源应用或终端到前台；分别记录目标会话和前台应用 |
| A5 | 重复标题、无项目分组、应用被遮挡 | 能定位时选择正确任务；无法唯一定位时说明能力缺口，不猜选其他会话，也不将仅唤起应用记为精确跳转通过 |
| A6 | 来源提供审批或回答接口 | 请求与来源任务对应；操作回传原请求，状态随后正确更新；没有回传能力的来源不能显示虚假的可操作按钮 |
| A7 | 来源退出、恢复和 AIsland 重启 | 任务不因应用进程仍在而永久运行；恢复不串会话，旧完成记录不重复响铃 |
| A8 | 接入设置与卸载 | 能识别接入状态和真实能力；需要配置的适配器可安装、刷新、卸载；保留用户原有配置 |

以上是五个来源分别验收的目标。发现某一来源只能做到应用级跳转或只能观察 UI，需记录具体差距并与用户讨论，不能自动降低完成标准。

### 模块与实现约束

先核对来源提供的 hooks、扩展、任务事件与跳转协议，再选择适配方式。优先来源公开接口；桌面端的内部事件不等于可配置的外部 hooks。CLI 与桌面身份独立，千问办公不复用 Qwen Code 的身份。适配器只读取所需任务元数据，沿用现有 bridge 和来源状态模型，避免修改第三方应用程序包。

预计涉及 `OpenIslandCore` 的来源标识、事件解码和安装管理，以及 `OpenIslandApp` 的发现、存活判断、跳转、设置和本地化。各适配器以一个来源的完整路径为一轮，保持单独验证与提交。

## 3. 自定义任务声音

### 用户结果

在“设置 → 声音”中保留系统声音，同时为“任务完成、等待审批、等待回答”分别提供选择、导入 MP3、试听、替换和恢复系统声音的操作。

建议将导入文件保存到 AIsland 的本地管理目录，用稳定标识记录选择，避免原文件被移动后声音失效。当前 `notification.sound.name` 只有一个值；升级时建议把现有声音迁移到三个类别，保持用户原有听感。

### 验收草案

| 编号 | 场景 | 可观察的通过条件 |
| --- | --- | --- |
| S1 | 为三类事件选择不同 MP3 | 每类显示正确文件名、能单独试听；真实事件播放对应音频 |
| S2 | 重启、移动或删除原始 MP3 | 已导入的声音和类别选择仍可使用 |
| S3 | 取消导入、选中损坏音频或伪装扩展名 | 有清晰结果反馈；原有选择保持有效，应用不崩溃 |
| S4 | 替换、删除或恢复系统音效 | 设置与实际播放一致；当前资源不可用时有稳定的系统声音回退 |
| S5 | 全局静音与快速连续事件 | 自动通知遵守静音设置；不会无限叠加或循环播放；手动试听策略在 UI 中清楚可见 |
| S6 | 从构建 5 升级 | 原有系统音效、静音与其他设置保持兼容；中英文均完整显示 |

播放长度、是否裁剪长 MP3、连续事件的排队或打断规则尚未定案。首轮应先提供可靠导入和播放，不把音频编辑器、按工具定制声音或声音商店自动加入本版。

预计涉及 `NotificationSoundService.swift`、`OverlayUICoordinator.swift`、`AppModel.swift`、`SoundSettingsPane` 和本地化资源。通知触发时需要传入具体事件类别，而不是继续共用一个声音名称。

## 4. 首次引导：画面、音效、触感联合设计

### 已选形式与建议流程

形式已经确定为全屏沉浸开场，随后进入简洁设置。下面分镜是 AIsland 的设计建议，不是对 Dia 实现的事实描述：

| 阶段 | 画面与用户操作 | 声音设计目标 | 触感目标 |
| --- | --- | --- | --- |
| 欢迎 | 桌面氛围收拢，Bloub 醒来，出现 AIsland | 从低强度起音到短品牌落点，随画面变化 | 自动演出不触发真实触感 |
| 理解刘海 | 图形连续变为屏幕顶部的刘海，多任务汇入 | 位移和落位有对应短声音，保留安静间隔 | 自动汇入不触发真实触感 |
| 学会响应 | 不同示例任务演示运行、完成、审批、回答和回到任务 | 三类事件各有可辨识的声音；示范点击有确认 | 模拟光标不触发真实触感 |
| 选择接入 | 用户选择本机工具，完成需要的设置 | 选择与真实安装成功分别反馈，失败不用成功音 | 仅在合适的用户操作与支持设备上试验；需用户实测 |
| 开始使用 | 全屏场景收回真实刘海，进入日常运行 | 声音收束，留下简短完成标记 | 自动收拢不触发真实触感 |

阶段 1 原型采用约 22 秒共同时间轴，比较两种原创合成声音方向；时长、曲线、音色仍待用户实际观看试听。音乐底层、转场音、交互确认共用时间轴；触感仅在符合平台条件的真实用户操作中安排。Apple 要求 `NSHapticFeedbackPerformer.perform` 响应用户发起的动作，且未触碰 Force Touch 触控板时可能不反馈；不能照搬 Pixel 欢迎动画的自定义马达曲线。引导中的示例状态与真实 bridge 隔离，示例安装成功不能代替实际结果。

### 验收草案

| 编号 | 场景 | 可观察的通过条件 |
| --- | --- | --- |
| O1 | 真正首次启动 | 自动进入完整引导；主显示器上的画面连续变化，清楚表达 AIsland 的核心用途 |
| O2 | 正常完成每一步 | 动效落点与音效起点、起落和尾音相配；支持的硬件上触感对应关键时刻；逐步记录视听触感结果 |
| O3 | 带声音观看与操作 | 用户认可完整视听效果；静态截图、静音视频、音频文件存在均不能代替这项验收 |
| O4 | 跳过、静音、减少动态效果、键盘操作 | 仍能完成配置；中断或跳步时同步取消过时的声音和触感，无隐藏播放残留 |
| O5 | 没有 Force Touch 触控板 | 引导流程和画面、声音仍完整；真实触感标为硬件不适用，与屏幕动效分开记录 |
| O6 | 设置页重播与完成后重启 | 可主动重播；正常启动不重复强制引导，不重复安装接入配置 |
| O7 | 现有用户升级 | 已有接入和设置保持；按已有首次启动迁移规则处理，不覆盖现有配置 |
| O8 | 多显示器、无刘海显示器和中英文 | 使用正确显示器和布局；结束后进入实际可用的刘海或顶部条，中英文操作完整 |

建议开场提供明显的跳过和声音控制，并尊重已有声音、触感与系统减少动态效果偏好。首次新用户的声音/触感默认值、开场时长和演示步骤仍待原型审阅。

预计新增独立引导窗口、视图和时间轴控制器，连接现有 `showOnboarding()`、`AgentIntentStore`、接入设置与实际 overlay。保持 C1 品牌轮廓及现有 Bloub 空闲节奏；具体新动效在引导场景内设计。

## 5. 推进与验证路径

用户确认计划后，先并行开展来源能力核验与扩展视听研究，并制作独立审阅原型。第一阶段在接入路线、声音交互与引导音画审阅处暂停；通过后再开始 Hermes / DeepSeek 的完整接入切片、原生三类声音导入和原生引导。其余来源待接口缺口补齐后实现，不默认为应用级跳转。具体阶段与停止条件见阶段 1 记录。

每轮选择与改动相称的检查并提交。新增来源需要验证来源协议、真实任务、并行归属和跳转；声音需要验证文件生命周期、类别映射和设置迁移；引导需要验证时间轴取消、首次启动/重播状态、真实视听和物理触感。

相关现有回归覆盖 Codex CLI 与 Desktop 的身份和 thread，ZCode 项目/独立任务的正确选择与前台状态，以及 WorkBuddy、Ghostty 的原有跳转。进入可交付运行时阶段后再进行完整 CI 和 Universal 包验证。实际安装与测试安排按交接要求另行明确。

## 6. 尚未完成的研究与设计

- Hermes、MiniMax 的外部 shell / plugin hooks 和 DeepSeek 桌面插件入口已有静态证据；千问公开企业 hooks 与会话导航已找到。所有来源仍需真实任务验收；MiniMax 的最终结果 / 精确导航、千问有效账号入口、豆包外部事件 / 导航仍有缺口。
- Dia 本轮完成公开录屏关键帧观察和本机音轨元数据/强弱分析；模型工具没有提供可听辨的音频输入，音色判断、完整步骤录屏及声画时间轴对齐仍未完成。
- 2025 年公开录屏与本机 Dia 1.51.0 的资源来自不同版本，不能直接把两个时间轴当作同一条。
- 已补 Google、Apple 和 Microsoft 的一手设计研究，并提供原创合成音画原型；原生首次启动、真实刘海收束、声音/触感默认值及听感仍需阶段审阅。
- 自定义长音频的播放长度和连续事件的播放策略待设计，不擅自加入裁剪器或固定长度限制。
