# v0.1.1 installed-source automatic event connections

Base: user-authorized `11037b9`, independent `feat/v0.1.1-auto-connections` worktree.

## Round 1 — CLI/extension detection and startup

The old startup only repaired `intent == installed`; untouched sources never
configured, Hermes was a view-local installation flow, and legacy migration could
replace an explicit removal. Configuration presence was not source-install evidence.

`AgentInstallationDetector` now checks regular executable CLI entry points in
explicit executable directories or exact app bundle identity plus its executable.
It does not execute source agents, inspect profiles, sessions or credentials, or
use leftover configuration directories as installation evidence. Roots are injectable.
`mcode` is excluded. Claude usage is optional and excluded from automatic task-event
configuration.

Startup scans, refreshes installation status, preserves legacy explicit intent,
and sequentially awaits missing event configuration. Detected untouched sources
are admitted; manually removed sources remain removed. Every startup and the Setup
"check installed agents" action scans again, so a source installed later is admitted
without creating configuration for absent sources. Configuration errors persist in
Setup. Repeated current configurations are skipped; Pi/OMP also use extension
version. Hermes uses `isCurrent`, allowing an owned old callback path to migrate.

Normal Hermes profile is configured through the existing YAML-preserving manager.
Only AIsland entries and its manifest change; no allowlist or auto-accept is written.
Default-profile Settings removal persists intent; custom profile operations do not
change normal-profile intent. Source consent remains Hermes' normal first-use flow.
Acceptance mode returns before source detection and configuration. It maintains only
the calling isolated preferences domain's migration/onboarding readiness.

Verification: App source compilation (`swift build --product OpenIslandApp`, not
bundle packaging or launch) passed. An isolated package uses unchanged production
Core/coordinator sources and fixtures; 23 tests cover installation evidence, later
installation, false directories/foreign bundle, preserved removal before migration,
normal Hermes configuration with no consent, idempotence, metadata adapter/reducer
receipt and acceptance-mode no-op. Fixtures are temporary homes and named defaults;
source Python is used only as the reviewed YAML parser. Simulation is not real agent
or UI acceptance. Three locale files pass `plutil`; diff check passes.

## Desktop deployment follow-up

The detector admits DeepSeek Harness Desktop and MiniMaxCode Desktop independently.
Round 1 does not claim their event plugins are configured. Existing integration
packages must be shipped as resources and installed using their reviewed ownership
contracts. DeepSeek official plugin composition requires its Desktop to be stopped;
MiniMaxCode requires an unambiguous active data directory and source-side plugin
activation. These restrictions must become explicit waiting states and completion
actions, without quitting source tasks, enabling mcode, reading session bodies, or
labeling a copied but unloaded plugin as a healthy connection.

No source-agent configuration or source UI was changed by this implementation round.
No formal App bundle was built. Real source/UI acceptance belongs to the main flow.

## Round 2 — first-run and stale callback repair

A fresh acceptance preferences domain previously never became migration-ready,
blocking the welcome claim. It now migrates using an all-false source predicate,
without reading or configuring any source. A fresh named-domain fixture proves
first presentation, completion and second-launch suppression. Merely detecting a
CLI remains insufficient to classify a fresh normal install as a legacy user.

Claude-format managers (including source-specific event subsets and ZCode's
nested layout) and Codex now expose `isCurrent`: an executable managed helper,
exact owned manifest command, complete expected lifecycle hooks and, for Codex,
an enabled feature. JSON formatting differences do not trigger rewrites. Startup
repairs stale configurations only for detected sources without explicit removal.
Temporary fixtures cover missing/old helper paths, partial Claude hooks, disabled
Codex feature and the coordinator's persistent manual-removal guard.

## Round 3 — native passive Desktop deployment

The App ships the reviewed DeepSeek and MiniMaxCode adapter packages as a copied
`AgentIntegrationPackages` resource. Their existing adapter files are byte-identical
to `Integrations/`; DeepSeek's additional configuration helper is new and tested.
Only exact installed Desktop bundles/version metadata are admitted: DeepSeek
`com.deepseek.dsh` / `0.2.0-rc.2`, MiniMaxCode `com.minimax.agent` / `3.1.0`. No source
task, Desktop UI, source login, mcode CLI or optional Claude usage integration is
started automatically. Explicit Settings “open source” remains a user action.

MiniMaxCode's active directory is inferred from the exact running bundle PID and
a bounded, birth-time-checked source descendant tree. Fixed-argv `lsof` returns
only open-file path metadata; admission requires one exact
`/v2/sqlite/runtime-state.sqlite` parent directory and rechecked process identities.
No SQLite contents, argv, source environment, session bodies or credentials are
read. An absent/ambiguous active directory requires explicit directory selection;
there is no fallback guess that `~/.minimax` is active.

The MiniMaxCode owned-only installer runs its dry plan and apply separately. It
validates the reviewed bundle, regular Node executable, plugin inventory/receipt
and hashes before writing. New plugins are copied to the confirmed active
`plugins/aisland-minimaxcode-passive`; owned current plugins are skipped; owned old
socket configurations migrate with a backup of plugin files, config, receipt and
compiled source probe. The helper and receipt remain in the owned support directory
(the previous owned directory is retained for migration). A Desktop-only install
no longer depends on an installed mcode package. Source classification still checks
actual native process identity, and CLI is disabled. The reviewed installer requires
a local Node runtime and Swift compiler for its external metadata probe; missing or
failing runtime/setup is shown as an error rather than a live-connection claim.

DeepSeek uses only the public normal `desktop` profile contract,
`~/.dsh/profiles/desktop`. An uninitialized normal profile waits for the source to
initialize it. A running source with configuration changes waits for user exit;
AIsland does not quit it or interrupt tasks. Once stopped, fixed argv invokes the
bundled official `dsh plugin --profile desktop add <owned-package>`. It writes the
owned adapter under AIsland support and the source's normal plugin dependency/lock
configuration. Existing linked adapters require byte-exact reviewed files or a
valid owned inventory/hash receipt; foreign same-name plugins are preserved.
Source profile files and previous owned package/receipt are backed up first.

DeepSeek's own row in `cordis.patch.yml` is then updated using the public bundled
YAML CST parser in Electron-as-Node configuration mode. The flat patch `id`/`config`
contract comes from public `dsh-app-boot/lib/index.js` / plugin-manager source. Only
`profileID`, `bridgeSocketPath`, and `navigationSocketPath` on our exact row change;
unrelated patches/comments, custom polling and source-disabled intent remain.
Opaque configuration is preserved without accessing auth/provider values. The
public `!!js` tag is retained as a string and never evaluated. The process runner
uses fixed argv, a minimal environment, bounded output and deadlines; on failure it
terminates only its own birth-time-checked spawned configuration family.

Settings distinguishes missing source, waiting for profile/exit/activation, copied
configuration and an actually received live session-start event. Copying files is
not represented as a healthy connection. The source owns activation/disable/remove;
“stop automatic setup” records a durable AIsland opt-out without pretending it
uninstalled a source plugin. Check-again/reconnect are explicit completion actions.
Errors remain visible; a successful waiting transition clears stale errors.

Verification: 31 production-source native fixture tests / 6 suites pass (including
process timeout cleanup); the independent first-run/current-hook slice passes
10 tests / 2 suites. The existing MiniMaxCode installer/source suite passes 18
Node tests, including Desktop-only setup without an installed CLI. One additional
DeepSeek CST test runs against the actual YAML module extracted only from the
public app archive, with no skip: comments/custom settings/disabled intent survive,
repeated updates are identical, foreign ownership and invalid YAML cause no write.
App source compilation passes in 7.01 seconds; three locale files and diff checks
pass. This is source compilation, not a formal App bundle build or launch.

All configuration writes in this round's tests target temporary fixture homes and
owned synthetic files. No real user source/profile/configuration, source UI, TCC or
clipboard was touched. Fresh normal-domain automatic setup, real source plugin
activation/exit/unique-directory inference and Settings presentation still require
main-flow UI/runtime acceptance after the user's formal bundle-build gate. Fixture
receipt is not real agent acceptance.
