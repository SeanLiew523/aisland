# v0.1.1 原生三类自定义声音首轮

状态：`IMPLEMENTED_PENDING_INTEGRATION_AND_NATIVE_REVIEW`。本轮是原生声音存储、播放与设置界面的可审查实现；浏览器原型上传/试听已经获得真人认可，不能据此宣称原生界面或听感通过。三类真实事件接线由主任务负责，完成集成后必须停在用户原生效果确认节点。

## 实现与接口

- `NotificationSoundCategory`：`completed`、`approval`、`answer`，三类独立保存系统音或自定义 MP3。
- `NotificationSoundService.playNotification(category:isMuted:)`：真实自动提示入口；旧无类别入口兼容映射为任务完成。
- `preview(category:)`：主动完整试听，按界面说明允许在自动提示静音时试听。`stop()` 立即取消并释放当前播放器；`setMuted(true)` 立即停止，需接入全局静音变化。设置页退出、导入、替换、切换系统音和恢复默认也会停止声音。
- `NotificationSoundStore`：可注入临时 `UserDefaults` 和目录，首次读取缺失的类别设置时从旧 `notification.sound.name` 迁移；保留旧 key。重新建立存储实例不会覆盖已经独立配置的类别。旧 AppModel 的单音设置接口仍兼容，新声音界面直接使用类别存储。
- 保留 `/System/Library/Sounds` 的全部 AIFF 系统音；自动提示和试听只有一个播放器，新声音替换旧声音，不排队、不循环。MP3 不可用时选用系统默认 Bottle；启动失败或 MP3 运行中解码失败只尝试一次 Bottle 回退，若回退也无法播放则结束，不循环重试。

设置页为每类提供系统声音/MP3 选择、完整试听、导入/替换与恢复默认；恢复或切换到系统音会清理该类别不再引用的托管 MP3。简体、繁体及英文文字在 `SoundSettingsPane` 内提供，不改其他设置区域。

## 文件生命周期

通过 `NSOpenPanel` 选择 MP3。检查扩展名、20 MB 大小上限、AudioToolbox 容器类型及 AVFoundation 实际解码后的正时长；解码首尾 PCM，拒绝仅改扩展名的 WAV、无法解码和空音频。文件先复制为临时文件，再在同一目录原子改名，成功后才更新类别选择和清理旧托管文件。权限、验证或改名失败都保留原设置与旧音频。

生产目录由应用运行时使用：`~/Library/Application Support/dev.aisland.app/NotificationSounds/`。稳定 UUID 文件名与原始显示名称分开保存，不长期引用 Downloads。解析/删除只接受本管理目录直接子文件中的 UUID MP3，拒绝目录和文件符号链接、路径越界，保留其他类别仍引用的文件。丢失/损坏不抹去显示元数据，设置页显示 Bottle 回退说明并提供替换或恢复操作。

本轮没有读取实际用户偏好、用户音频或生产 bridge，没有安装/启动 AIsland，也没有操作 v0.1.0 签名、公证与发布候选。

## 尚待用户确认的播放策略

## 聚焦修复：静音事件与播放失败（2026-10-03）

独立审阅指出首轮两个实际缺口：被静音的自动事件会在早退前停止正在主动试听的声音；MP3 准备成功后 `play()` 返回失败没有执行文档所述的回退。本轮只修改声音服务、播放控制器、对应专项测试与本记录，保持设置界面与其他模块不变。

- 服务与 Core 播放入口先判定自动事件静音，再停止/替换当前音频。静音事件不准备音频、不调用播放器、不执行回退，也不干扰用户主动试听。用户切换全局静音仍由 `setMuted(true)` 立即停止；测试覆盖“试听 → 静音自动事件 → 试听继续 → 主动全局静音 → 停止”。
- 所有声音启动失败最多调用一次 Bottle 工厂；该次回退自身失败就结束。主动预览的回退完整播放，自动事件与其回退共用单调时钟 `ContinuousClock` 的原始截止时间，不重新开始一个 5 秒预算。
- MP3 包装播放器新增 `AVAudioPlayerDelegate` 解码错误处理，将回调交付到 MainActor。每次服务请求创建独立包装播放器；Core 还检查当前 generation 和播放器 identity，停止时先清除 handler 再停止音频。停止、替换或静音之后的迟到回调不会启动回退，也不会停止新音频。Bottle 回退自身的运行中失败结束播放，不再尝试下一次回退。
- 此实现针对 `play()` 启动返回值与 AVAudioPlayer 报告的 MP3 解码失败；无法输出的系统音频设备不是“保证可听”的条件。若 Bottle 启动也失败，最终结果是无活动播放器，没有重试循环。NSSound 未报告的运行中输出故障不被记作已实现的回退能力。

复验：`swift build` 通过；隔离 Swift Testing 全部 **20 项、2 suites** 通过，其中新增 6 项验证静音事件保留试听、启动失败与失败回退限制、运行中失败及迟到回调、停止/替换后不能回退、自动截止时间不重置，以及预览回退完整播放。`git diff --check` 通过。音频输出依然全部使用假播放器，未播放设备、启动应用、读取生产偏好或访问 bridge；临时验证 package 与日志收尾删除。原生真人视听和真实事件集成仍待主任务后续确认。
