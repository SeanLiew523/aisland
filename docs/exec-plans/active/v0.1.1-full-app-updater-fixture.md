## Admission contract

The ordinary bundle retains the fixed public GitHub latest endpoint and HTTPS release asset policy. JSON cannot decode a fixture policy. Neither environment variables nor preferences enable the local endpoint.

`UpdaterFixtureConfiguration.current(bundle:)` validates boolean `AIslandUpdaterFixture`, `OpenIslandRuntimeAcceptance`, and `AIslandUpdaterFixtureSupported`, strong update configuration, dedicated random `dev.aisland.v011.acceptance.upd-<16hex>` ID, and realpath of the running bundle. Only `/private/tmp/aisland-updater-app-fixture-<32hex>/installed/AIsland.app` is admitted; its ID must match the root suffix. The immutable plist supplies `AIslandUpdaterFixtureRoot` and `AIslandUpdaterFixtureOrigin`. Origin must be exactly HTTP `127.0.0.1` with one explicit port between 1024 and 65535, without credentials, path, query or fragment. Assets must remain at that same origin and release path. Only display versions 0.1.1/0.1.2 are admitted.

Malformed marked bundles fail closed. UpdateChecker stores the configuration error and refuses the check, without falling back to a public or local installer. Local metadata redirect responses are rejected. Signed feed and archive validation, own public key, exact version/URL/length selection and user download/install consent stay active.

RuntimeAcceptanceConfiguration is owned by the source-setup worker. Its `current` must first obtain this validated object from the actual Bundle path. Only that typed admission permits 0.1.2; ordinary acceptance stays 0.1.1. Source discovery/setup remains disabled and socket/registry/preferences stay in the random acceptance case. The acceptance builder records `AIslandUpdaterFixtureSupported=true` only after compiling this interface.

Fixture receipts record launch process/version, phase and download bytes only. They do not prove the Settings UI was visible or correctly reopened, and contain no source task/session content.
