# v0.1.1 GitHub stable release updater

Status: implemented and locally verified; production delivery and full AIsland Settings acceptance are pending.

## Behavior and trust

Settings → About → Check for Updates queries public GitHub latest stable release metadata for `SeanLiew523/aisland`. Disabled bundles can query version information, but cannot install. Drafts, prereleases, malformed numeric versions, downgrades and assets outside the exact release path are rejected.

A newer release needs an uploaded `appcast.xml` asset. The bundle must explicitly trust an AIsland Ed25519 public key with `AIslandUpdateSigningIdentity=aisland-ed25519-v1`, `SURequireSignedFeed=true`, and `SUVerifyUpdateBeforeExtraction=true`. The legacy upstream key is rejected and no longer defaults into packaging. GitHub supplies metadata; Sparkle 2.9 validates the feed/archive, checks OS/build compatibility, replaces the bundle and relaunches. Feed short version, archive URL and length must match the same GitHub release. Informational/paid major upgrades and Sparkle signed-feed fallback items are rejected.

Settings presents version, release notes, bytes/progress, preparation, installation/restart and errors. One explicit Download, Install & Restart action authorizes installation/relaunch after download. Checks are manual. A recovered update cannot relaunch without consent. Download completion is never presented as installation success. Cancellation is available before extraction; termination can be retried if the app delays quitting.

## Required publication conditions

Live public check on 2026-10-04: latest is `v0.1.0`, containing `AIsland.dmg`, `AIsland.zip`, `release-metadata.json`, and `SHA256SUMS.txt`. No `appcast.xml` asset exists. Root appcast has no items. Existing packages disable updates and omit public key/feed.

The release owner must confirm an AIsland-owned public trust anchor and retain its private key in the signing environment. This task does not create/read/write/import a production private key. Production credentials and publication are outside this change.

Future packaging can opt in with `OPEN_ISLAND_DISABLE_UPDATES=false`, `AISLAND_UPDATE_SIGNING_IDENTITY=aisland-ed25519-v1`, and `OPEN_ISLAND_EDDSA_PUBLIC_KEY=<confirmed public key>`. Defaults remain disabled. Use an explicitly monotonically increasing `OPEN_ISLAND_BUILD_NUMBER`; the display version must match the GitHub tag without `v`. Verify actual Developer ID signing/notarization and Sparkle helper signing; an ad-hoc local fixture does not prove production signing policy.

Publish the compatible ZIP/DMG, sign the archive, and generate/sign `appcast.xml` using Sparkle `generate_appcast`. Upload the feed as an asset of that same stable release. Its enclosure must use the exact GitHub asset URL/length, incremented build number, and release display version. Do not modify the feed after signing. Already installed disabled v0.1.0 bundles need the first configured build installed manually; these source changes cannot add trust retroactively.

## Verification

- `swift build --product OpenIslandApp`: passed, including settings and Sparkle 2.9 interfaces.
- `python3 scripts/test-updater-isolated.py`: actual production updater sources/tests copied unchanged into a disposable package. Covers version ordering, release/asset admission, trust flags/legacy keys, public request/rate limit, progress/cancel, recovered-update consent, and disabled-bundle discovery.
- Normal targeted `swift test` is blocked by unrelated repository `Testing`/CLT setup. Isolation uses the already installed framework, changes no unrelated tests and replaces no toolchain.
- `python3 scripts/verify-sparkle-isolated-update.py --run`: actual Sparkle signature verification, v1→v2 fixture replacement, automatic relaunch, receipt read from the new process, installed bundle version 2, and strict signature verification.
- `--run --tamper-archive`: archive corruption rejected, fixture remains v1.
- `--run --tamper-feed`: feed corruption rejected, fixture remains v1.
- Packaging shell syntax, public-config positive/absent/malformed/legacy-key checks and diff checks passed.

Fixture isolation: random `/private/tmp/aisland-updater-fixture-*` directory and `dev.aisland.updater.fixture.*` bundle ID; loopback server; ephemeral CryptoKit Ed25519 private key exists only in signer-process memory. Only that fixture is launched/replaced. Callback events/new version are recorded; fixture files/preferences are removed afterward. No production app, hooks, bridge state, signing keychain or notarization is touched.

This verifies the Sparkle installer mechanism. Full Settings → GitHub release → AIsland installation acceptance remains pending. It needs the approved publication conditions and isolated old/new AIsland bundles with a dedicated test ID and isolated runtime admission. Verify visible settings progress/errors, closing/reopening settings during download, same-path relaunch, new version/signature, and byte-identical production AIsland afterward.
