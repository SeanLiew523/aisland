## 共用 bridge 契约

沿用 UTF-8 NDJSON / Unix socket，生产默认 `~/Library/Application Support/OpenIsland/bridge.sock`；`OPEN_ISLAND_SOCKET_PATH` 可覆盖。日期沿 `BridgeCodec` 使用 **Unix 毫秒数值**。

```json
{"type":"command","command":{"type":"processRuntimeLifecycleHook","runtimeLifecycleHook":{"source":"deepseekHarness","event":"turnStarted","profile_id":"desktop","session_id":"real-session","turn_id":"real-turn","sequence":123,"cwd":"/project","timestamp":1791000000000,"app_bundle_id":"com.deepseek.dsh","app_conversation_id":"real-session","navigation_socket_path":"/profile/deepseek-navigation.sock"}}}
```

`source` 只接纳 `hermesCLI` / `deepseekHarness`；`event` 为 `turnStarted`、`turnCompleted`、`turnFailed`、`turnInterrupted`、`sessionEnded`。`profile_id` / `session_id` / `cwd` / `timestamp` / source / event 必填；回合事件必须有非空 `turn_id`，sessionEnded 可省。`sequence` 为可选非负整数。可选 `source_observed_start` 是 Bool；来源插件重载后未观察 start 时标 false，同回合结束只收拢，不响完成。可选 `result_reason` 仅准入固定 coarse 枚举，不放错误正文；Hermes形如 `local_processing_error(body)` 只留下 `local_processing_error`。可选定位字段包括 `terminal_app`、`terminal_session_id`、`terminal_tty`、`tmux_target`、`tmux_socket_path`、`warp_pane_uuid`、`app_bundle_id`、`app_conversation_id`、`navigation_socket_path`。回执仍为现有 acknowledged。

会话键采用 source + profile + 原 session 的长度限定 namespace。接收端拒绝旧时间、旧 sequence、已经见过的 start、旧回合结束和重复结束；仅观察到同回合 start 的明确成功产生完成通知。失败、中断与会话退出保持明确结果文案，不产生成功通知或回复按钮。sessionEnded 是关闭会话，回合结束不关闭会话。

持久化 ledger 只存身份、状态和定位元数据，路径为 bridge 目录内 `runtime-lifecycle.json`。重启加载后所有 start 降为未观察；observer 注册时恢复运行或结束状态，结束回执全部静默，不重播完成提示；运行中回合继续由下一次真实事件及既有进程存活路径更新。

## Hermes

核对本机源提交 `0ff4c748658ff5b92661fa2b453fcf8ed813414d`：`pre_llm_call` 是回合开始；`on_session_end` 带 completed / failed / interrupted / turn_exit_reason 和 turn ID，是回合结果。`post_llm_call` 不参与成功判定。中断补发如果缺少 turn ID，无法安全匹配，明确忽略；进程退出使用存活检查收拢，不能猜结束当前回合。

`OpenIslandHooks --source hermes --profile-id <profile-directory>` 只提取必要身份与结果。用户正文、工具参数、history 不进入 bridge、ledger、摘要。沿用现有 host inference；终端只取 env、父进程 TTY、multiplexer ID 和 Warp PID 关联，不读取当前焦点猜来源 pane；沿用原有跳转服务，不把仅唤起终端记为准确跳转。

设置页新增 profile 与 Python 可选入口，支持刷新、安装/更新与卸载。默认 profile 为 HERMES_HOME 或 `~/.hermes`；默认解析器为 Hermes 安装自身的 `hermes-agent/venv/bin/python`，允许选择其它带 PyYAML 的解释器；本机已按此默认路径实读确认可执行与 PyYAML 6.0.3，当前 CLI 入口为 `~/.local/bin/hermes`。没有解析器时显示具体阻塞，不加软件依赖或退回脆弱文本猜测。

配置操作保留其它原项与 hooks 下用户条目；仅重写 hooks 映射，映射内格式/注释可能变化。其它部分原始文本保留，首次改动保存 `config.yaml.aisland-backup`（0600）。拒绝重复 YAML key、非映射/非列表 hook、flow root 与 hooks anchor，不写入不明确格式。写入前复查原文件，检测并发变化后停止。

归属清单为 profile 内 `aisland-hooks.json`；卸载只删除清单记录的精确命令，保留其它 hook 与 Hermes 的 consent 文件。配置没有 `hooks_auto_accept` 或自动 allowlist 写入；状态分配置与已记录授权。用户应重启 Hermes，在其自己的 TTY 提示确认两条 hook。记录授权不等同实际任务已验证。

## DeepSeek 原生导航

生命周期把 `profile_id` 与 `navigation_socket_path` 保留到 `JumpTarget.runtimeProfileID` / `runtimeNavigationSocketPath`；appConversationID 为真实 session。原生跳转调用插件独立导航 socket，不使用 `dsh://open` 猜会话。

```json
{"version":1,"action":"openSession","request_id":"UUID","profile_id":"desktop","session_id":"real-session"}
```

每连接一条 newline JSON；回执必须匹配 version / request_id / profile_id / session_id，且 status=`dispatched`。这只证明公共 `uiWorkspace.openSession(ID)` 被调用；真实选中与前台仍要观察。拒绝 `selected`、失败、错误ID、缺身份与超时，失败不会继续执行应用激活 fallback；dispatch后调用现有 openAction 激活 `com.deepseek.dsh`，文案明确“已发送定位请求，核对来源中的选中会话”。

默认 socket 与 bridge 同目录为 `deepseek-navigation.sock`，按 payload 路径、`OPEN_ISLAND_DEEPSEEK_NAVIGATION_SOCKET_PATH`、bridge默认目录顺序选择。socket连接为 nonblocking，连接就绪后检查 SO_ERROR；非阻塞写入与读回执共同使用从入口计算的两秒 deadline。确定性测试包括正确receipt、request/profile/session/version/status mismatch、不存在endpoint、不回ACK，以及 peer不读导致写缓冲满，后者30ms deadline内结束（允许0.3秒调度裕量）。没有启动真实 DeepSeek 客户端；插件安装归插件工作流，只有下一真实效果节点才能确认准确导航。
