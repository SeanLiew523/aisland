# MiniMaxCode normal Copy-stage diagnostics

This slice preserves Desktop 3.1.0 admission, exact native-ID verification, the original three-second navigation budget, and guarded clipboard restoration. It does not claim that the observed normal-app A-to-B Copy failure has been repaired. Real source/UI acceptance remains with the integration workstream.

An existing, empty, current-user-owned `0600` regular file at `~/Library/Application Support/OpenIsland/.minimax-copy-diagnostics-enabled` opts the normal app into diagnostics. The app creates neither the marker nor a missing directory. It appends `minimax-copy-diagnostics.log` in the same directory, with a 64 KiB cap and nonblocking exclusive lock. Marker/log symlinks, hardlinks, foreign ownership, non-0600 permissions, special files and redirected ancestor directories are rejected without repair. Removing the marker stops new records.

Each Copy attempt records a timestamp, closed stage/reason/cleanup vocabulary, focus query error/count, whitelisted focused AX role, booleans, entry budget and elapsed milliseconds. No source text, title, native ID/hash, clipboard value, workspace path, or geometry is retained. Disabled ordinary navigation performs no extra diagnostic AX query; an enabled attempt may query the focused element's role. Existing acceptance-bundle diagnostics remain separate.

The record distinguishes title/menu admission, exact Copy focus, input delivery permission, ID submenu availability, label activation and clipboard observation. `deadlineExpired` retains the stage reason that consumed the budget instead of replacing it with a generic timeout. A late exact clipboard copy is restored but still cannot become navigation success.

Pre-existing renderer menus are rejected using the same title scan before opening a menu. Failed attempts try targeted `AXCancel` only for the menu observed after their own title-button press, while source PID/version, window, frontmost app and current menu-focus ancestry still agree. Cleanup has a separate 120 ms budget; it never activates an app, sends a global Escape, or affects copied bytes. `cleanup=unsupported` means the admitted menu did not offer `AXCancel`; it does not prove closure. User focus changes or unowned menus suppress cleanup. The actual renderer's cancel support and closure require normal-app observation.

Verification uses isolated filesystem fixtures, injected controller metadata fixtures and named synthetic pasteboards. No source GUI, real clipboard, source database, profiles, markers or configuration are touched by this worker.
