# MiniMaxCode Desktop existing-session navigation

## Scope and source contract

This slice implements exact existing-conversation focus for the admitted MiniMax Code Desktop 3.1.0 (`com.minimax.agent`) surface. It requires the observed native session ID and explicitly admitted metadata database path/version in `JumpTarget`; it does not infer a default database or a session URL. Shared jump-service wiring and real bundled-app acceptance belong to the integration workstream.

Public source was inspected from `/Applications/MiniMax Code.app/Contents/Resources/app.asar`, using the prepared `output/verification/v0.1.1-live/minimaxcode/source/asar-index.json` offsets. The renderer project header has the exact accessible label `<project name>, <workspace path>` and contains its own task rows. The live verifier separately observed the native draggable project group, exact header button, and child exact-title buttons. DOM classes can identify the same group but are not mandatory. The selected task topbar has title text followed by an unlabeled menu button, an IDE chooser, and a terminal opener. This is a structural heading check, never a body-text match.

Bundled locale chunk `88822-20ca4c0699fa9c5a.js` supplies the exact public labels `Copy` / `复制`, `Copy session ID` / `复制会话 ID`, `Choose IDE` / `选择 IDE`, and `Open terminal` / `打开终端`. The public menu's Copy session ID action is the final native identity check. No configurable default shortcut, private IPC, diagnostic HTTP, injected JavaScript, or guessed deep link is used.

## Metadata and navigation boundaries

`MiniMaxCodeNavigationMetadata` opens the admitted `/v2/sqlite/runtime-state.sqlite` read-only. It validates a concrete table and metadata column types/primary key, binds only the observed ID, and authorizes only explicit column reads plus the read transaction and aggregate normalization functions. It never selects `record_json`, input/error payloads, body/history, auth, or project alias JSON. The exact row and duplicate-title aggregate share a committed SQLite snapshot. The aggregate returns only a count; other session metadata is not returned.

Only visible, unarchived, root task/conversation/unknown sessions with columnar version 3, positive project ID, and explicit workspace project metadata are supported. Default workspaces, child sessions, version/schema drift, views, missing metadata, and normalized duplicate titles fail closed. Duplicate titles across projects also return unavailable; exact selection among duplicate titles is not claimed.

The controller requires one running matching source process and a unique admitted main window. Among at most eight source windows, exactly one must have `AXWindow` / `AXStandardWindow` and the exact public title `MiniMax Code`; that candidate must report main=true and minimized=false. Unknown attributes and duplicate standard-window titles reject selection. Auxiliary dialogs cannot become the navigation root. The project/native-ID checks also reject a same-title login or onboarding window. It searches the unique exact project-path header and its smallest matching project ancestor within three parent links, bounded to 500 nodes/eight levels for task-row selection. It may expand that project once. It never widens a failed project lookup into a whole-sidebar title search. After selecting the unique task button, it opens the structural topbar menu, presses the public Copy submenu and Copy session ID action, and strictly compares the resulting bounded native ID. It then re-reads the metadata and confirms the same process is frontmost.

Clipboard items/types are preserved in memory with bounded size. Restoration occurs only while the pasteboard change count still matches the observed copy operation; a subsequent producer's copy is not overwritten. Clipboard bytes and native ID results are not logged or persisted by navigation.

## Application routing

`TerminalJumpService` now recognizes the exact `com.minimax.agent` desktop bundle and forwards the complete admitted `JumpTarget` to this verifier. Only `.focused` reports conversation success; an unavailable identity, source, project, or foreground throws a navigation error. No new workspace or conversation is opened. MiniMaxCode CLI remains deferred under the user's current instruction and does not use this desktop route.

The routing tests inject a diagnostic sink, preventing synthetic success/miss messages from becoming production navigation evidence. The default diagnostic sink uses the isolated acceptance case directory in an acceptance bundle; ordinary production logging retains its existing directory. The App compiled after this wiring. The two focused routing tests validate metadata preservation and rejection without workspace fallback; real bundled-app navigation is still pending.

## Accessibility availability diagnostics

The controller now checks an injected availability probe before source/metadata/UI
navigation. Production uses `AXIsProcessTrusted()` without prompting or changing
permissions; injected test UIs default to available. A denied or revoked grant
returns `accessibility-unavailable` before selecting/activating/copying, and a grant
revoked during selection stops the Copy session ID operation. A trusted UI with a
missing sidebar remains `sidebar-conversation-unavailable`. Neither case creates
a task or treats application activation as successful conversation navigation.

This distinguishes actual TCC availability from a structural lookup failure. An
OS entitlement warning alone does not prove which one occurred. The acceptance
bundle's current permission state and exact navigation still require root's live
verification; this worker does not change permission settings or operate source UI.
