外部 session 深链契约。主进程 Deep Link 只负责 focus/broadcast；renderer 的

生产桌面没有默认 localhost listener，HTTP 为可选 diagnostic sidecar。未接这个通道、
未附着 private MessagePort，也未修改 source app/package。

## 原生只读 reader / monitor 实现轮次

新增 `MiniMaxCodeMetadataReader.swift` 与值类型 `MiniMaxCodeLifecycleMonitor.swift`，不改
共享 reducer / BridgeServer / App 文件。主 Agent 的 serial queue 调用
`observe(_:now:)` 与 `poll(now:)`，再由其持有 250 ms timer。monitor 只登记已收到
`sessionObserved` 的 MiniMax 来源，要求明确版本和 DB 路径，最多 128 个来源/profile/
session cursor；每个 cursor 保留最多 256 个已见 turn。没有全局 DB 会话扫描。

每次 reader 使用 `SQLITE_OPEN_READONLY`，短连接、20 ms busy timeout，仅校验指定表
schema 并执行参数绑定的六列白名单查询。SQLite authorizer 进一步拒绝其他表或列，
包括伪装为 ingress 的私有内容视图。异常只暴露粗错误 enum，不返回 DB 错误正文。
reader 不创建源目录/DB，不执行迁移、恢复、更新或锁写入。

确切 native turn ID 查询保留 exact session + turn，不限制历史终态的时间窗，供重启后
静默同步；monitor 会拒绝把 admission floor 之前的旧 accepted 当成新 start。
无 turn ID 则仅从已观察 session 的 `accepted_at_ms >= Hook 时间减 2 秒` 区间里取
最新 accepted sequence，再钉住原生 ID。真正观察到 accepted 后才发 `turnStarted`，
带原生 accepted sequence；终态带 committed timestamp，sequence 不造假递增。
若第一次看见的就是终态，只发 `sourceObservedStart:false` 的真实 end，禁止制造 start
或新增成功提醒。历史/重复/其他回合不能结束新当前回合；迟到 Stop 不移动旧 admission
floor 或替换 active identity。源暂不可读只记录 unavailable metadata gap，不猜成功。
awaiting/idle cursor 在 90 秒后移除；每次成功读到 live accepted 会延续观察期限。

`observe(sessionEnded)` 先查询已钉住回合的真实终态，再解除监听，返回 DB 派生事件；
BridgeServer 另在这些输出后处理原始 `sessionEnded`，它本身仍非成功结果。

验证：Core 构建通过；完整 Core 源码 + 新来源专项测试在临时隔离 package 中，
**11 项 Swift Testing 全通过**，覆盖 WAL 未提交/已提交差别、真实 reducer 的成功/失败/
中断、native-ID 缺失时的会话/时间过滤、终态首见、重启旧终态静默同步、旧 accepted
不重开、不同回合迟到、重复 Stop、schema/私有视图拒绝、类型与终态时间异常、缺失/关闭
DB、来源版本、profile/source 隔离及 128 上限。未读取任何真实来源 DB 或改变用户配置。

常规 `scripts/test-clt.sh --filter MiniMaxCodeMetadataTests` 失败于本机已有
`no such module '_Testing_Foundation'`；隔离 runner 使用 CLT Testing framework 和

## Native bridge connection

BridgeServer now admits MiniMaxCode only from session observations/releases,
then polls committed metadata on its serial queue every 250 ms. Source-supplied
turnStarted/turnCompleted cannot directly fabricate a notification. SessionEnd
first settles committed terminal facts, then releases the observed session.
Stop remains an admission signal. Teardown cancels polling and clears ephemeral
cursors. Production Core compilation and 23 isolated lifecycle/SQLite/bridge
checks pass, including a real socket observer proving no completion until the
DB transaction commits and no private input_json in transmitted events.

The live-source receiver in scripts/verification/runtime-bridge.swift uses the
production codec, reducer and observer with an explicitly isolated socket. Its
receipts contain identity, state, coarse result and navigation metadata only.
It never reads or exports user message bodies. These fixtures/receiver checks
are separate from real MiniMaxCode app/CLI and native UI acceptance.

## 共享插件目录的真实来源识别修复

桌面与普通 CLI 默认同用 `~/.minimax/plugins` 和 DB。两个固定来源 config 会把 CLI
误标桌面，所以原生 Hook 改为每次只读识别真实来源，未识别不发送。新增 reviewable
`scripts/source-probe.swift`，在插件目录外编译；最多读 16 个祖先进程的 PID、PPID、
executable path、内核 start time 和原 controlling TTY（`proc_bsdinfo.e_tdev`）。不读
argv/env、fd、提示词、消息、auth，不启动来源，不改来源安装包或用户配置。

CLI 0.5.3 `cli.js` 在普通 TUI 运行前注册、finally 删除原生 active marker；
`chunks/chunk-ZZOIWHZG.js` 的 `re(e=process.argv[1])` 根据实际安装 prefix 写
`.mcode-active/<PID>.json`，内容只有 `{pid,startedAtMs:Date.now()}`。TUI embedded
runtime 留在该进程，Hook shell/命令为后代。适配器只读明确 prefix 的公开 package
身份/版本和每个确切 ancestor PID marker（最多 1 KiB、拒绝 symlink/nonregular），
并要求 marker 时间在该 PID 内核 birth 与 Hook birth 之间，拒绝旧 PID 重用。

桌面要求 ancestor executable 位于 canonical app `Contents/`，并验证实际 Bundle ID
`com.minimax.agent` 和版本 3.1.0。Hook 自身 interpreter 不参与来源判定；若 mcode
位于桌面内置终端，较近 CLI marker 优先。中间未知 Node、版本不匹配、stale marker
或 helper 不可读均静默，不将它们回退归为 desktop。normal `mcode` 入口完全保留。

新增 config `sourceDiscovery` 含 `probePath`、`desktopAppPath`、`cliPrefix` 的绝对路径，
`allowedSources`（初始仅 desktop）和可选 source-specific `profileIDs`。分类出的 actual
version/source/profile 覆盖固定 config 后才投影 wire。CLI 可附带 original `terminal_tty`
和来源祖先中明确识别的 terminal app；没有 pane UUID，不宣称精准原 pane 已验收。
安装器需额外复制 `scripts/source.mjs`，在插件目录外编译 helper，先针对 installer
own PID 做一次只读预检，以覆盖 macOS 新 executable 首次校验 1–2 秒延迟；之后 Hook
probe 200 ms deadline，超时 fail open。卸载只删已登记 owned helper 和插件安装。

本轮验证覆盖共享桌面/CLI配置、桌面内嵌 mcode、未允许 CLI 不误标、缺失/旧/未来/
