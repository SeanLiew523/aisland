# v0.1.1 approved V6 native welcome

Status: native runtime and startup/settings integration implemented; real-window
acceptance remains required. The approved V6 media is unchanged.

## Runtime

AppKit borderless full-display window, a flipped CGContext scene view, decoded
native sprite frames, native SwiftUI skip/mute/reduced-motion controls, and
AVAudioPlayer. No HTML renderer or WKWebView is shipped. The reviewed 22-second
scene equations, native rows, native clips, final short title beats, timeline
and hardware geometry are ported from fixed V6 commit `32c94f2`.

Media preload finishes before the score starts. One scheduled audio device
clock drives all visual times; silent fallback uses monotonic system uptime.
Mute leaves that clock running. Reduced motion uses stable native stills and
removes travel/pulse/background motion, while preserving the timed sequence.
Esc skips, Command-W closes, and teardown restores prior presentation options
and releases the window, timer, observers, media and audio. Screen changes
re-read safe areas and notch bounds. Full frame (not visibleFrame) reaches the
hardware notch; its covered central gap stays between character and agent grid.

## Root integration contract

Call `OnboardingPresentationStore.claimAutomaticPresentation(migrationReady:
firstLaunchCompleted:)` after hook status reads and legacy migration, immediately
before `OnboardingWindowController.present(language:completion:)`. It writes
`onboardingPresentedV1` promptly. A partial first presentation / quit consumes
automatic replay regardless of existing `firstLaunchCompleted`; legacy completion
suppresses presentation without rewriting it. The caller persists completion or
skip with the existing intent store and opens existing Setup settings. Replay
calls `present` explicitly and does not reset either key. Termination calls `stop`.

Resolve `OnboardingLanguage` from existing manual app language plus preferred
system languages. English uses English media; all Chinese forms use the approved
Simplified Chinese media. Resolution never changes saved en/zh-Hans/zh-Hant/system
preference. Controller does not access production defaults or hook configuration.

The main agent owns AppModel/startup/SettingsView/localization/package glue.
This slice owns Onboarding sources, resources, policy, tests and this document.

## Startup/settings connection

The app delegate waits for completed hook status reads and legacy migration
before claiming automatic presentation. Completed or skipped intros finish the
existing first-launch intent and open Setup. Closing midway consumes the
presentation claim without marking setup complete. Subsequent startup and
legacy upgrades do not replay; General settings provides an explicit replay.
Manual app language takes precedence over system preferred languages without
changing either preference. Global mute is applied before scheduled audio starts.
Optional haptics honor the existing app preference and reduced-motion setting,
with no burst of missed beats after a stalled frame. Termination tears down the
welcome before stopping notification playback.

App target compilation and the isolated native/policy checks pass. These checks
do not yet establish real installed-app first/second launch or audible playback.

## Independent full-app acceptance infrastructure

`RuntimeAcceptanceConfiguration` only admits a plist CFBoolean
`OpenIslandRuntimeAcceptance=true` together with
`dev.aisland.v011.acceptance.<case>`. It validates v0.1.1/build >= 6, source SHA,
and the fixed approved V6 SHA. Invalid opted-in metadata throws; the app delegate
must stop that launch instead of using production defaults/paths. Ordinary
bundles remain outside this mode. No environment variable enables it.

Each case has `/tmp/aisland-v011-acceptance/<case>/bridge.sock`, adjacent isolated
`runtime-lifecycle.json`, and `welcome-receipts.jsonl`. POSIX realpath admission
rejects production/legacy paths and symlink redirects, including missing path
tails. Case preferences use the full dedicated bundle identifier. Root glue must
skip runtime discovery, private source status reads, hook installation and
production registry access; migrate the case intent store with
`detectInstalled: { _ in false }`, then use the normal automatic welcome claim.
Do not bypass the resolver or force OnboardingLanguage.

Receipts expose only claimed/shown/exited welcome events, typed exit result,
resolved language, bundle/source/baseline, two store flags and
`Locale.preferredLanguages`. They have no session/body/message fields. Record
welcome claims, actual successful window presentation, exit, or the next-launch
claim decision separately; a receipt is an observation, not acceptance itself.

The build script defaults to plan-only. For example:

```sh
python3 scripts/build-v011-acceptance-app.py --case zh-first \
  --socket /tmp/aisland-v011-acceptance/zh-first/bridge.sock --build-number 6
```

Only after the main agent confirms all four real sources, explicitly add
`--build`. It builds the current clean committed repository products, copies
both helpers, complete resources, Sparkle, committed branding and licenses,
records source/V6 provenance, and uses the existing `Open Island Dev Local`
identity. It creates a fresh bundle under `output/v011-acceptance`, refuses
existing destinations, and never installs, launches, kills apps, writes language
preferences, installs hooks, creates certificates, packages DMGs, or notarizes.
It reports `runtime_acceptance_verified=false`; building is not runtime evidence.

Reuse the same case bundle/domain for first and second launch. Chinese and
English use separate case domains and app process `-AppleLanguages '(zh-Hans)'`
and `-AppleLanguages '(en)'`, leaving `appLanguage=system`. Existing manual choice
cases use their own domains. Root owns actual launch/close/skip/upgrade/replay,
audio and hardware-notch evidence; this infrastructure slice does not run apps.
