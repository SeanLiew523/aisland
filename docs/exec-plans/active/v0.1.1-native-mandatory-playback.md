# Mandatory native first launch

The user's latest first-launch contract supersedes the earlier skip/close
acceptance baseline: automatic first presentation must show the full-screen
22-second native sequence without review controls or any manual pause/cancel.
This slice preserves the approved V6 sprites, audio, geometry and shared clock;
R7 media review is separate and unchanged.

`OnboardingPlaybackMode.autoMandatory` only permits the natural 22-second ending.
There is no controls hosting layer: mute, motion toggle, skip, clock/progress and
explanatory text are removed from both automatic playback and replay. Starting
mute/haptic preferences and system Reduce Motion continue to apply. No system
volume setting is modified. Esc/Cmd-W are consumed, `windowShouldClose` refuses
mandatory close, and ordinary application hiding is disabled for that sequence.
The application must use `isMandatoryPlayback` to refuse ordinary Cmd-Q/menu Quit
through `applicationShouldTerminate`; no Force Quit/kill/power behavior changes.

`explicitReplay` uses the same clean scene but allows Esc/Cmd-W/window close with
`.closed`. The controller never modifies first-launch presentation/completion
state. Root owns delegate wiring for automatic/replay modes, quit gating and
store handling. Screen configuration changes retain the timer during mandatory
playback; if a screen disappears, the controller does not treat that as a skip.

Validation passed: `swift build --target OpenIslandApp` (50.45 seconds), and
11 isolated tests across 3 suites (including the 2 new playback-mode tests,
7 language cases and 36 native offscreen scene renders). The policy tests deny
skip/close/early completion for mandatory playback and allow only replay close.
The retained legacy completion-store test does not represent an available skip
control in the current native UI. No full bundle was built or app launched.

Live full-screen Esc/Cmd-W/Cmd-Q attempts, natural completion, second launch,
Settings replay cancellation, mute/haptics/Reduce Motion and source-specific
navigation stay pending until root's real app acceptance. No UI is run here.

Root integration: automatic presentation explicitly selects `autoMandatory`;
the Settings replay action selects `explicitReplay`. The application delegate
returns `terminateCancel` during mandatory playback for menu Quit/Cmd-Q. The
noninteractive AIsland wordmark is retained in the scene; review controls are
absent. The reusable isolated test runner now includes the mandatory policy
suite. All 11 tests and the app target build pass after this wiring. Actual
full-bundle first-launch verification remains pending.

Live build 8 on the actual Chinese system locale (`zh-Hans-CN`, `en-CN`), with
no language override, shows a borderless full-screen image and retained wordmark
only. Esc, Cmd-W and Cmd-Q were attempted within the first 5 seconds; all were
refused. The welcome naturally completed and recorded `firstLaunchCompleted`.
The initial Settings fallback did not open a window: the custom SwiftUI Settings
command does not supply `showSettingsWindow:`. The fallback now invokes the same
own-app menu action as Cmd-comma and also identifies the settings window by its
stable identifier, since the selected pane changes its title. App compilation
passes; a fresh full-bundle launch must verify this correction. The Watch sidebar
item is absent in the real settings UI.
