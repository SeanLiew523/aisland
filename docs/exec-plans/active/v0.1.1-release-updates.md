# v0.1.1 signed release updates

The requested slice enables download/install/automatic relaunch in formal
packages. Existing UpdateChecker/Sparkle callbacks already implement the UI
flow; the missing public trust/delivery configuration is now provided.

- Dedicated Ed25519 identity: `aisland-ed25519-v1`, public configuration in
  `config/packaging/AIslandUpdates.json`. The private key was created with the
  pinned official Sparkle tool and remains in its dedicated local Keychain
  account. It was not exported or uploaded.
- Formal packaging is Universal, Developer ID signed and Hardened Runtime,
  with updates enabled, signed-feed and pre-extraction verification required.
  Source input/commit changes during packaging reject completion. Existing
  output artifacts are preserved. The developer builder and explicit CI smoke
  packages retain updates disabled.
- The exact final ZIP and per-release feed are signed with the dedicated key.
  Verification uses the committed public key only, checks archive/feed bytes,
  source/version/build/download URL, extracted ZIP and mounted DMG. Duplicate
  signing trailers and unsigned trailing contents are rejected.
- The Release workflow validates locally prepared signed/notarized draft
  assets and promotes only verified releases. Private keys stay off CI, and
  CI cannot substitute an ad-hoc package. Actual Apple tickets and Gatekeeper
  checks are required for public publication. No v0.1.0 candidate or monitor
  is changed.
- Native end-to-end validation uses a separately admitted random domain copied
  from the release artifact, with isolated preferences/runtime paths and
  ephemeral in-memory fixture signatures. It tests the actual full release
  executable/resources through Settings while preserving installed v0.1.0.
  It does not claim public GitHub delivery or upgrade from the disabled old
  executable. v0.1.0 build 5 still requires a manual first upgrade.

Focused checks passed: 6 actual Ed25519 verification/tampering cases, 9
isolated updater admission/cleanup checks, and 13 Swift updater/runtime
configuration tests. The new duplicate-signature rejection test failed before
its strict suffix fix and passed afterward; failures were not counted as passes.
Shell/Python syntax and `git diff --check` passed. Native release-copy execution
and complete package verification follow; Apple notarization remains separate
from build success.
