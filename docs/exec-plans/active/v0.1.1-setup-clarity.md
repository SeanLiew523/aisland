# AIsland connection setup clarity

Based on `729fa30`, this slice changes only the connection setup page, its three locales, the shared installation prerequisite explanation, and the Hermes setup row.

The former gray Install buttons did not indicate that Qoder, Qwen Code, Factory, or CodeBuddy was absent. They were disabled solely when AIsland's hook executable could not be located. Pi, Oh My Pi, and OpenCode use bundled extension/plugin files and did not require that executable. Source-app installation is not checked by these rows. Runtime acceptance skips ordinary source discovery and configuration; the former enabled extension buttons could therefore do nothing. The page now gives that mode its own visible reason and disables writes. Hermes observes the same mode and does not start source-status reads there.

The page calls the action Configure AIsland Connection, distinguishes detected connection files from a verified working connection, and explains unknown/unread configuration separately from not configured. Existing hook status continues to come from the actual configuration/file managers rather than a stored intent or whether the agent executable happens to be installed. No new source-app detection or connection-health claim is introduced.

Claude-format connection installation copies `OpenIslandHooks` into AIsland's managed Application Support bin directory, merges AIsland event callbacks into the agent's settings, backs up changed existing settings, and writes an installer manifest. Pi/Oh My Pi installation writes `extensions/open-island.ts` and its AIsland manifest in the selected agent directory. OpenCode installs the bundled AIsland plugin. None installs the source agent. The existing bulk action explicitly says it writes configuration for every listed agent, including absent source agents; the page recommends individual rows for the agents actually used.

Verification uses compilation, localization lint, and fixture-only coordinator tests. No real agent installation, source configuration mutation, session-body/credential read, or UI operation is part of this slice. Real layout/readability, missing-helper versus acceptance-mode explanations, configured rows, and a user-approved regular-app configuration remain integration acceptance checks.

Verification results: `OpenIslandApp` compiled (47.81 s initial build, 11.52 s final build); all three localization files passed `plutil -lint`. The ordinary filtered test build hit an existing CLT Testing incompatibility in `TerminalJumpServiceTests` (`Test.cancel` unavailable), unrelated to this slice. An isolated macOS 14 package copied actual production Core, coordinator, LanguageManager, ResourceBundle, RuntimeAcceptanceConfiguration, localization files, and the unchanged coordinator test file; all six coordinator tests passed. New checks cover missing-helper hooks versus helper-free extensions and acceptance-mode disabling despite a located helper. Existing fixture tests verify independent Pi/Oh My Pi status reads and corrupted manifests. No real user-agent installation or user configuration write occurred. The isolated package was removed after the run.
